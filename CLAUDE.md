# WeatherTempo — Claude Code Context

Personal weather dashboard for Christchurch NZ. GitHub Pages + GitHub Actions data pipeline. WeatherGraph-style canvas chart.

## Quick Commands

```bash
# Development server
python -m http.server 8080
# Then visit: http://localhost:8080

# Test the data fetch script locally
cd scripts && WEATHER_API="your_key" python fetch_weather.py

# Check GitHub Actions workflow status
gh run list --workflow=update-weather.yml --limit 5

# Visual test (requires Playwright MCP)
# (Screenshot chart at different viewport sizes)
```

## Architecture Quick Reference

**Data Flow:**
```
.github/workflows/update-weather.yml (every 30 min)
  ↓
scripts/fetch_weather.py (uses WEATHER_API secret)
  ↓ fetches from:
    - PWS: /v2/pws/observations/current (current conditions, ICHRIS810 station)
    - Open-Meteo: /v1/forecast (hourly + daily forecast, free ECMWF model)
  ↓
data/weather.json (auto-generated, DO NOT EDIT MANUALLY)
  ↓
index.html → src/app.js loads data → populates chart + cards
```

**Frontend Structure:**
- `src/app.js` (1248 LOC) — data loading, card population, sample data fallback
- `src/chart.js` (835 LOC) — WeatherChart class, canvas layers, Catmull-Rom bezier curves
- `src/tides.js` (328 LOC) — harmonic tide predictor using Lyttelton LINZ constants, J2000 epoch
- `src/locations.js` (250 LOC) — location management

## Critical Files (DO NOT EDIT MANUALLY)

⚠️ **`data/weather.json`** — Auto-generated by GitHub Actions every 30 min. Manual edits will be overwritten and cause merge conflicts.

- To change data structure: Edit `scripts/fetch_weather.py`
- To debug data issues: Check Actions tab → Update Weather Data workflow logs

## Chart Architecture (src/chart.js)

**ZONE object** defines pixel-perfect meteogram layout (364px total height):
```
Main zone (0-224px):   temperature, feels-like, cloud, pressure  [70%]
Wind zone (228-276px): red speed line + arrows, MAX_SPD=90km/h   [15%]
Precip zone (280-328px): blue precipChance area + qpf bars      [15%]
Time axis (332-348px): hour labels, day separators
```

**Critical:** Zone pixel constants must maintain 70/15/15 split ratio. If editing ZONE, verify all 8 constants (cloudTop, cloudBot, tempTop, tempBot, windTop, windBot, precipTop, precipBot) remain consistent.

**Drawing layers:**
1. Background grid + separators
2. Cloud overlays (fillStyle rgba with cloud cover %)
3. Temperature area (Catmull-Rom curve + gradient fill)
4. Wind indicators (arrows every 3 hours at windTop + 24px offset)
5. Precipitation bars + area fill
6. Pressure polyline (white, secondary axis)
7. Hover tooltip layer

## Data Sources (Hybrid Approach)

**Current conditions:** Weather Underground PWS API
- Endpoint: `/v2/pws/observations/current?stationId=ICHRIS810`
- Auth: `apiKey` query param (WEATHER_API secret)
- Metric data nested: `observations[0].metric.temp`, `.windSpeed`, `.pressure`, etc.
- Top-level: `humidity`, `uv`, `winddir`, `solarRadiation`

**Hourly + Daily forecast:** Open-Meteo (free, no key)
- Endpoint: `api.open-meteo.com/v1/forecast`
- Params: `latitude`, `longitude`, `hourly`, `daily`, `timeformat=unixtime`
- WMO weather codes mapped to TWC-style phrases/icons in fetch_weather.py

**Why hybrid?** PWS API tier doesn't include hourly/daily forecasts. Open-Meteo provides ECMWF model data for free.

## Gotchas & Warnings

1. **Canvas coordinate precision**: Chart uses integer pixel coordinates. Floating point causes blurry rendering—always use `Math.floor()` or `|0` for pixel positions.

2. **Catmull-Rom tension**: Temperature curve uses tension=0.5. Lower values (0.3) create smoother curves but may overshoot; higher values (0.7) stay closer to points but look angular.

3. **Wind arrow rotation**: `drawWindIndicators()` uses degrees clockwise from north. Canvas rotation is radians counter-clockwise from east → convert with `(winddir - 90) * Math.PI / 180`.

4. **Tide J2000 epoch**: `calculateTideHeights()` uses J2000.0 (2000-01-01 12:00 UTC) as reference. Any date math must account for this epoch when working with LINZ harmonic constants.

5. **PWS metric nesting**: All metric values (temp, wind, pressure) are nested under `observations[0].metric` object. Top-level observation has non-metric values (humidity, uv, winddir). Don't mix them up.

6. **GitHub Actions cron**: Workflow scheduled for every 30 minutes but currently DISABLED (commented out in update-weather.yml line 4-5). Data updates happen only on manual workflow_dispatch trigger. (Note: May be replaced by Cloudflare Worker per comment.)

7. **Moon phase calculation**: Uses synodic period (29.530588 days) from J2000.0 reference new moon. This is astronomical calculation, not API data—moon phase is computed in fetch_weather.py, not fetched.

## Customization Hooks

**Change location:**
1. Update `LAT`, `LON`, `STATION_ID` in `scripts/fetch_weather.py`
2. Update location text in `src/app.js` (search for "Christchurch")
3. Update `<title>` in `index.html`

**Change tide station:**
1. Get LINZ harmonic constants for your port: https://www.linz.govt.nz/sea/tides/tide-predictions
2. Replace the constituents array in `src/tides.js` (M2, S2, N2, K1, O1, etc.)
3. Update STATION_NAME in tides.js
4. **Verify:** Compare first 3 tide predictions against LINZ official data before committing

**Customize chart appearance:**
- Colors: `CHART_COLORS` object in chart.js
- Wind arrow style: `drawWindIndicators()` method
- Temperature gradient: `createTemperatureGradient()` method
- Precipitation bar width: `barWidth` calculation in `drawPrecipitation()`
